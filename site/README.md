# site/ — статические страницы tralebot.com

Генератор публичных индексируемых страниц (раздел «Грамматика» и будущие разделы).
Живёт рядом с мини-аппом, но по другим правилам — см. раздел «Сайт vs мини-апп» в `../CLAUDE.md`.

## Как это устроено

```
site/
  build.mjs            генератор (Node ≥ 20, единственная зависимость — marked)
  site.config.json     baseUrl, username бота, токены верификации, доп. URL для sitemap
  lib/template.mjs     HTML-каркас + инлайн CSS в стиле лендинга (Minankari)
  lib/frontmatter.mjs  парсер front matter (подмножество YAML)
  content/<раздел>/    _index.md — страница раздела, <slug>.md — страницы тем
  static/              файлы, копируемые в корень сайта как есть (верификация GSC/Яндекс)
  test/                node --test
```

Сборка пишет в `../src/Trale/wwwroot/` (тот же каталог, откуда ASP.NET отдаёт SPA):

- `/grammar/index.html`, `/grammar/<slug>/index.html`
- `/sitemap.xml` (корень, legal-страницы, разделы и все не-draft страницы)
- файлы из `static/`

`index.html`, `assets/`, `audio/` мини-аппа не трогаются. В Docker сборка идёт в первой (node) стадии сразу после `vite build`, поэтому на проде страницы появляются вместе с очередным деплоем образа.

## Как добавить страницу

1. Создать `content/grammar/<slug>.md` (slug — латиница, цифры, дефис; он станет URL `/grammar/<slug>/`).
2. Front matter:

```
---
title: Заголовок для <title> и превью        # обязательно, уникальный
h1: Заголовок на странице                     # опционально, по умолчанию = title
description: 1–2 предложения для сниппета     # обязательно, уникальный
order: 20                                     # порядок в списке раздела
related: [cases, postpositions]               # slugs соседних страниц → блок «Смотрите также»
draft: true                                   # noindex + нет в sitemap; снять, когда текст готов
updated: 2026-09-14                           # lastmod в sitemap и dateModified в JSON-LD
source: откуда взяты факты                    # для ревью
---
```

3. Тело — Markdown (GFM): таблицы, списки, ссылки. Пример с переводом оформляется цитатой из двух абзацев:

```
> კაცი მუშაობს
>
> Мужчина работает
```

4. `npm run build && npm test`. Грузинский текст автоматически оборачивается в `<span lang="ka">`.

## Верификация в Search Console и Вебмастере

Либо meta-теги — заполнить `verification.google` / `verification.yandex` в `site.config.json`,
либо файловый способ — положить выданный файл в `static/`. См. `static/README.md`.

## Что с страницами глаголов (`/verbs/<глагол>`)

Идея: по странице на глагол с полной таблицей спряжения, данные только из базы проекта.
Аудит данных на 2026-09-14:

| Источник | Что есть | Чего нет |
|---|---|---|
| `src/Trale/Lessons/**/*.json` (2898 вопросов, 773 леммы) | лемма, перевод, варианты ответа, объяснение, аудио | нет ни одной структурированной парадигмы «лицо × число × время» |
| `MiniAppContentProvider.cs` (теория) | отдельные ряды форм в тексте (например, ვწერდი … წერდნენ для имперфекта) | формы разбросаны по строкам `List(...)`, без привязки к лемме |
| PostgreSQL | словарь пользователей (VocabularyEntry), прогресс | справочных грамматических таблиц нет |
| `content-audit-verb-system.md` | список фактических ошибок в вопросах по глаголам движения | — |

Вывод: генерировать `/verbs/*` сейчас нечем — 0 глаголов с полными данными из 773 лемм.
Нужен отдельный источник (например, `site/data/verbs/<lemma>.json` с явными полями
`present/imperfect/aorist/future × 1sg…3pl`), заполненный и проверенный носителем.
Пока такой базы нет, страницы глаголов не делаем — иначе получится правдоподобное враньё в индексе.
